01

Doctrine — ten rules that outrank everything below

Any future proposal that violates one of these needs an explicit founder decision, not a quiet exception.

D1One bloodstreamA single Postgres (Supabase, Mumbai) every organ reads and writes. tenant_id + RLS on every table from day zero. "How is this child doing?" is a join, and joins don't cross databases.
D2Organs, not chatterModules own their tables, never reach into another's, exchange typed events (evidence.confirmed), and expose abilities as tools. Agents coordinate through shared state — the blackboard — never by talking to each other.
D3Five primitivesEvery step is CODE, AI STEP, DECIDE, AGENT, or GATE. The test: a rule a coordinator could write on paper is CODE; a bounded judgment is DECIDE; only a path that can't be known in advance is an AGENT. The system has exactly two agents.
D4Drafts, never silent decisionsNothing reaches a child, parent, record, or coordinator decision without its gate. Every generated artefact carries "drafted by the system, confirmed by [name] on [date]". No trail → not switched on.
D5Nothing hard-codedEvery structural fact — bands, subjects, scales, traits, report forms, frameworks, prompts, decisions, flows — is a table row. Adding Grade 5 or a new framework is data entry, never a code change.
D6Intelligence upstreamSpend AI at design time so run time is mostly lookups. Misconception-tagged distractors, approved pedagogy, alias tables, golden sets: assets compound; API calls don't. Expect tokens-per-child to fall each term.
D7Reviewer-minutes are the constraintEvery gate is a diff (Accept · Edit · Skip), built once as one shared confirm component. Decision confidence triages what deserves human attention. Approval grain matches human capacity (topics, not 1,750 objectives).
D8Derived data is disposableEvidence is append-only; the graph and coverage are pure functions of it, rebuilt nightly, TRUNCATE-able any time. The graph reads confirmed evidence only.
D9Loops write backThe system learns only through write-backs to versioned assets — prompts, thresholds, edges, priors, golden sets. State improves; the runtime stays dumb and auditable. No self-modifying agents.
D10Children are protected by architecturePII in its own schema with roles, retention and an access log. Pseudonymised tokens only to any external AI service. Safeguarding concerns route synchronously to coordinator + head, bypassing every queue. Isolated observations never become permanent labels.

03

The decision fabric

Bounded judgments — too fuzzy for code, too narrow for a generative model — go through one interface. TypeSafe's Jev (released 19 Sep 2026; typed Noul/Choice/Score outputs with calibrated confidence; text-only; vendor figures $0.042/M input, 70–500 ms, unvalidated on our workload) is the first provider, never a dependency.

decide(decision_id, state, evidence) → { answer, confidence, model, model_version, instruction_version, timestamp }
providers: jev | claude-structured | rules | human   — caller never knows which answered

decision registry (a table, like everything): decision_id · engine · question_type (noul|choice|score)
  · input_schema · possible_outputs · instruction_version · confidence thresholds (autonomous|review|manual)
  · human_gate · fallback · evaluation_dataset (golden set) · owner · created/updated
  • Confidence policy: high confidence + low consequence → automate and log · high + consequential → only if policy permits · medium → teacher/coordinator review · low → fallback or manual · conflicting evidence → escalate · sensitive developmental inference → never auto-persisted, regardless of confidence.
  • Graduation rule: every decision-id is advisory until it beats its golden set on our own data. Teacher overrides are the labels. Golden set #1 exists today: Maya ma'am's voice notes.
  • Where the fabric runs: observation fan-out, residual name matching, open-response error classification, report-line verification, attention scoring (advisory). Where it doesn't: assessment triggers, orchestration paths, approvals, mastery interpretation, curriculum quality — those are rules, thresholds and gates by D3.
  • Privacy (D10): external decision APIs see C-142, never a name. DPDP diligence before any child data reaches production use of a new vendor.

The knowledge graph in use

fails 3-digit subtraction→ error tag: regrouping→ graph: is place value secure?→ target the deepest insecure prerequisite
  • Diagnosis descends along precedes: remediation targets the actual gap, not more worksheets on the surface skill. Readiness ascends: "ready for Grade 3" = coverage over the Grade-2 frontier; the handover report falls out of the same query.
  • Edges are curriculum content: drafted by AI at authoring, approved by the council like any other object (engine 1's required output), later audited by evidence — reliable co-failure of X and Y proposes an edge.
  • Child state is an overlay on this graph, per level_set, never averaged across scales. No graph database: the Postgres closure table answers every query at this scale.

The voice flow — pilot flow, fully specified

1 · teacher records (WhatsApp / one button)→ 2 · context pack: timetable + day_override + rosters + aliases→ 3 · ASR, roster keyterms→ 4 · names: code rules → DECIDE residue; collisions never auto-resolve→ 5 · AGENT extracts 4 streams→ 6 · DECIDE: enter-state / review / recurring per instance→ 7 · confirm queue <2 min, confidence-sorted→ 8 · write; nightly rebuild; tomorrow's draft
  • Every confirmation writes back to the alias table, and the teacher gets a 5-line "what the system now knows about your class this week" — a teacher who sees nothing come back stops on day four.
  • Unconfirmed rows move to the coordinator view after 48 h; both adults in a room record under their own names; an absent child cannot receive an instance; safeguarding bypasses everything, synchronously.

Verification — how we know it works

  • Structural: loader idempotence (re-run = zero diff, exact counts, zero dangling refs) · fake-Grade-5 test — adding a grade via screens only; any code change = design failed · Playwright screenshot per lens at desktop + 400px · retired codes resolve on cold load · evidence written before a publish still resolves its old descriptor · graph TRUNCATE + rebuild is byte-identical.
  • Intelligence: gold table + CLI from Phase 3 day one — ASR WER, name-resolution precision/recall, extraction F1 on every prompt change; per-decision golden sets with calibration audit (does 0.9 confidence mean right 9 times in 10 on our data?); drift watch on every decision-id.
  • Human: pilot stop rules — confirm queue >5 min/day for a week or >⅓ items corrected → fix the prompt or observables, never lower the bar · Saturday observer-bias report · flow_run cost line on the job-health page, so tokens-per-child is a graph we watch falling.

The moat, restated once: anyone can rent Jev, Claude, and Postgres. The compounding assets — a misconception-tagged bank aligned to our skill map, pedagogy proven in our classrooms, per-child longitudinal evidence, and golden sets that let automation earn trust decision by decision — exist only here, and every loop above makes them richer. Engines can be rebuilt; the assets are Cornerstone.
