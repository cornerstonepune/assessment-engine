# W1 — the question bank as engine code

**Goal:** `engine bank fill SUB.2D.EXCH Hard --n 200` produces 200 verified items in the `item`
table from a skill-set spec that is entirely rows, and `engine bank sheet` renders them into a
PDF a teacher can hold. No per-topic Python. ADR 0005.

**Architecture:** the skill-set spec (`skill_set` row + `config` philosophy + `misconception`
rows) is filled into the `item_generate` prompt row; the Gemini adapter returns JSON; the
verifier recomputes every number and rejects what fails; accepted candidates become `Item`
objects in the exact shape the existing generators produce, get taxonomy tags, and land
`status = active` (the schema's word for approved). A staff flag row retires an item by trigger.

**Deviation from the writing-plans format:** code is not repeated here; it is written directly
in the files below, tests first. This plan holds the file map, the order, and the checks.

## Order

1. Migration applied to the hosted project; seeds and loader; `engine load --check` green with
   the new counts. (Task 1)
2. `compute` and the `predict` guard, with tests. (Task 2)
3. `verify.py` from failing tests, including the three malformed items the spike produced as
   regression cases. (Task 3)
4. `llm.py` from failing tests with `urlopen` monkeypatched: placeholder fill, retry on
   404/429/503, ordered fallback, schema rejection, `flow_run` row. (Task 4)
5. `bank.py` and the CLI; live test inside a rolled-back transaction. (Task 5)
6. Real run: fill 200, recheck, render a sheet, hand the PDF to Nimish. STATE, HANDOFF,
   DECISIONS-LOG. (Task 6)

## Success criteria — each is a command

1. `cd packages/engine && uv run pytest -q` → all green; at least 15 new tests.
2. `uv run engine load --check` → `skill_set 4`, `config 2`, unchanged on a second run.
3. `uv run engine bank fill SUB.2D.EXCH Hard --n 200` → accepted ≥ 160, then
   `select count(*) from item where status='active' and source='generated'` ≥ 160; running it
   again adds no duplicate `item_key`.
4. `uv run engine bank recheck` → `0 mismatches` after recomputing every active generated item's
   answer and predictor table from its spec.
5. `uv run engine bank flag <item_key> --by nimish --note "…"` → that item's status is `retired`
   and `bank sheet` never picks it.
6. `uv run engine bank sheet SUB.2D.EXCH Hard --n 12` → a PDF and key JSON in `data/bank/`, rendered
   through the existing renderer unchanged.
7. `uv run engine eval item_generate` → pass rate per skill set × difficulty printed; the number
   goes into DECISIONS-LOG next to the prompt version.
